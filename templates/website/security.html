{% trans "Isolation between clinics" %}

{% trans "Every clinic table enforces PostgreSQL row-level security, so application code cannot read another clinic's records." %}

{% trans "The application connects with a database role that cannot bypass row-level security and does not own the schema." %}

{% trans "A record from another clinic gets the same refusal as a record that does not exist, so a refusal reveals nothing." %}

{% trans "Access and accounts" %}

{% trans "Privileged roles confirm an authenticator code, and sensitive actions ask for a fresh one." %}

{% trans "Permissions come from versioned role bundles; a released bundle is never edited in place." %}

{% trans "Invite staff by role; access starts only after a password and an authenticator are confirmed." %}

{% trans "Records and audit" %}

{% trans "Changes are recorded in a hash-chained audit ledger whose rows the database refuses to update or delete." %}

{% trans "Audit entries carry only the clinic, the request and the outcome, never patient data." %}

{% trans "SOAP notes are drafted on the server; finalizing makes the version immutable and asks for a fresh authenticator code." %}

{% trans "Privacy by design" %}

{% trans "Patient identifiers and searches travel in form bodies, never in page addresses or logs." %}

{% trans "The browser keeps no clinical text: the offline cache holds only versioned static files." %}

{% trans "Patient names are stored encrypted and found through keyed exact-match indexes, with no plaintext copy." %}

{% trans "AI with limits" %}

{% trans "AI never diagnoses, prescribes, finalizes a note or sends a clinical message on its own." %}

{% trans "Consent to record is not consent to AI: drafting needs its own consent and an enabled organization policy." %}

{% trans "Every suggestion shows its source and waits for the clinician to accept, edit or reject it." %}

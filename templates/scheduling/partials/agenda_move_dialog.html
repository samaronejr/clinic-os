The move form comes first (start time, Cancel, Move) and posts the revision the board rendered; the slot finder asks the server for the professional's free times on another day; the action section offers only the lifecycle actions the board rendered for that appointment (data-actions). JS off never reaches it: each movable appointment POSTs its selector to the native move form, and the list view and holds panel carry the other actions as native forms. Cancel is a plain button closed by the script: HTMX owns this form's submit event, so a formmethod="dialog" submitter would never reach the browser. {% endcomment %}
